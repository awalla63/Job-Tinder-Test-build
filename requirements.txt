# CPU-only torch wheels. Without this, `pip install torch` on a Linux host (e.g. a
# Render deploy) pulls the CUDA-enabled build by default -- several GB versus a few
# hundred MB, and pointless here since inference runs through ONNX (see ml/encoder.py),
# not torch's own CUDA path. Harmless locally on Windows, which already resolves to a
# CPU wheel from plain PyPI.
--extra-index-url https://download.pytorch.org/whl/cpu

# --- ML ---
#
# The encoder stack is pinned. Left unpinned, a fresh install (first Modal build) resolved
# an optimum 1.x alongside transformers 5.x, which fails to import -- and ml/encoder.py
# would then silently fall back to plain PyTorch. optimum-onnx (latest 0.1.0) caps
# transformers below 4.58, and sentence-transformers 6.x requires transformers >=5, so
# sentence-transformers stays on 5.7.0, the newest release that accepts 4.57.

# encodes as several chunks and the speedup compounds per chunk).
